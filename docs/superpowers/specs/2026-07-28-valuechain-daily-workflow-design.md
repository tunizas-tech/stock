# 밸류체인 매일 1개 축적 워크플로 — 설계

작성일: 2026-07-28

## 목적

산업/테마별 밸류체인을 하루에 하나씩 꾸준히 쌓는다. 리서치와 작성은 Claude가 하고,
사용자는 브라우저에서 초안을 확인한 뒤 공개를 승인한다.

## 사용자 흐름

1. 사용자: "오늘 밸류체인"
2. Claude: 백로그 맨 위 미완료 항목을 리서치 → `src/lib/valuechains/<slug>.ts` 생성
   (`status: "draft"`) → 확인 URL과 함께 판단이 애매했던 종목을 보고
3. 사용자: `/valuechain`에서 초안을 열어 확인
4. 사용자: "공개해줘" (또는 수정 요청)
5. Claude: `status: "published"` 전환 → 백로그 체크 → 커밋·푸시

사용자가 하는 일은 두 마디와 브라우저 확인뿐이다.

## 변경 사항

### 1. 산업별 파일 분리

현재 `src/lib/valuechains.ts` 단일 파일에 모든 체인이 들어 있다. 1개당 약 115줄이라
30개면 3,500줄이 되어 편집이 어려워진다.

```
src/lib/valuechains/
  index.ts                     배럴 — 각 파일을 import해 VALUE_CHAINS 구성, getValueChain 제공
  sk-eternix-renewable.ts      기존 시드 이관
  <slug>.ts                    매일 하나씩 추가
```

`index.ts`의 공개 API(`VALUE_CHAINS`, `getValueChain`)는 그대로 유지한다. import 경로가
`@/lib/valuechains`로 동일하므로, 파일 분리 자체로는 소비 지점(목록 페이지, 상세 페이지, 테스트)에
수정이 발생하지 않는다. 페이지 수정은 아래 "초안 상태" 때문에 별도로 일어난다.

### 2. 초안 상태

`ValueChain`에 필수 필드 `status: "draft" | "published"`를 추가한다. 필수로 두어야 새 파일에서
빠뜨릴 수 없다. 기존 시드는 `published`.

- 목록 `/valuechain`: **공개 / 초안 두 그룹**으로 나눠 표시. 초안을 숨기지 않는 이유는 개인용
  로컬 앱이고, 숨기면 검수하러 들어갈 링크가 사라지기 때문이다. 초안 카드에 "초안" 배지.
- 상세 `/valuechain/[slug]`: 초안이면 상단에 "검수 전 초안" 배너.

### 3. 백로그

`docs/valuechain-backlog.md` — 다룰 산업을 순서대로 적은 체크리스트. Claude가 맨 위 미완료
항목을 꺼내 쓰고 공개 시점에 체크한다. 초기 목록은 Claude가 20~30개 초안으로 채우고 사용자가
순서·항목을 수정한다.

## 정확도 규약

리서치를 Claude가 수행하므로 오분류·환각을 막는 규약을 둔다.

- 출처 **2개 이상 필수**. `sources` 필드에 기록한다.
- 각 종목의 `role`은 출처에서 확인된 사업 내용만 적는다. 추측한 관련성은 적지 않는다.
- 확신이 낮은 종목은 체인에 넣지 않고, 초안 전달 시 "확인 필요"로 따로 보고한다.
- 기존 `disclaimer` 필드를 유지해 투자자문이 아님을 명시한다.

## 테스트

`src/lib/valuechains.test.ts`를 확장한다. `VALUE_CHAINS` 배열을 순회하므로 새 파일이 추가되면
자동으로 검증 대상이 된다.

- 슬러그 유일성
- `stages`와 각 `stage.nodes`가 비어 있지 않음
- `status`가 `"draft" | "published"` 중 하나
- `sources`가 2개 이상

## 비목표

- 브라우저 [공개] 버튼 — DB 저장이나 dev 전용 파일 쓰기 API가 필요해 작업량 대비 이득이 적다.
  공개 전환은 Claude에게 말하는 것으로 충분하다. 데이터가 쌓여 파일 관리가 불편해지면 그때 재검토한다.
- 밸류체인 데이터의 DB 이전 — git에 남는 편이 되돌리기 쉽고 배포 시 DB 의존이 없다.
- 뉴스·보유 종목 기반 주제 자동 추천 — 백로그 순서대로 진행하기로 했다.
